# Два критика: последовательные проходы ЧЕТЫРЕ

Проверки выполнены последовательно одним агентом с разными критериями. Это не отчёт о запуске независимых субагентов

## Круг 1. Новичок без кода

Объект: body.html, затем собранные article.md и index.html

1. Термин App Router появлялся в запросах без объяснения. Добавлено в шаге Perplexity: способ организации страниц Next.js, адреса задаются папками и файлами; официальный источник рядом
2. Библиотека в разделе Context7 не объяснялась. Добавлено: готовый набор функций для разработки, который подключают к проекту
3. После проверки Context7 читатель оставался внутри Claude Code, а финал предлагал сразу ввести claude. Перед общим тестом добавлен явный /exit, затем запуск нового сеанса
4. Правка исходного подключения с неверным ключом могла задеть другое место хранения. Объяснено: удалить только этот сервер и в исходном scope; конкретная команда Firecrawl относится к --scope user этой инструкции

## Круг 1. Структура и факты

1. Абзац Playwright повторял анонс другой статьи. Убран, перекрёстная ссылка осталась в «Дальше по теме»
2. При первичной сверке README маршрут Perplexity с ключом мог быть принят за отмену OAuth. Дополнительно открыта официальная справка: OAuth поддерживается. В статье выбран один путь с ключом; в sources.md и отчёте различены выбор пути и изменение сервиса
3. Подготовка говорила «Perplexity понадобится ключ» без указания, что это выбор нашего маршрута. Исправлено на «Для выбранного подключения Perplexity понадобится ключ API»
4. Canary в готовом запросе мог быть непонятен. Добавлен русский смысл: тестовая сборка
5. Markdown-источник склеивал подписи карточек и метки участников диалога. Исправлен перенос текста при сборке article.md

## Круг 2. Новичок без кода

- Пройден маршрут: открыть папку и терминал, проверить программы, посмотреть существующие серверы, получить ключи, подставить только YOUR_API_KEY, запустить Claude Code, вызвать /mcp, проверить инструмент, выйти перед следующим подключением
- Perplexity: где взять ключ и куда вставить; результат содержит официальный источник, дату и версию
- Playwright: npx запускает нужный пакет, API-ключ не нужен; результат требует существующего скриншота и адреса
- Firecrawl: вход через аккаунт, возвращение в Claude Code, отдельный вариант с ключом, объяснён ограниченный набор без аккаунта
- Context7: назначение документации, библиотека и версия объяснены, отсутствие точной версии не скрывается
- Общий тест применим без установленного Next.js и не меняет файлы, даёт видимые результаты всех четырёх вызовов
- Существенных пробелов по письменному маршруту после правок не найдено. Живые экраны остаются отдельной приёмкой Claude по ТЗ

## Круг 2. Структура

- Каждый из четырёх инструментов отвечает на пять вопросов канона 2а: ситуация, назначение и место работы, механизм с бытовым сравнением, ограничение, установка с проверяемым результатом
- Начало открывает вопрос о версии уверенного ответа; последний нумерованный шаг закрывает его через Perplexity и Context7, дополняя прочитанной страницей и файлом браузерной проверки
- Движение пользы: источник → наблюдаемая страница → содержимое → документация под версию → общая задача
- Проблемные случаи стоят перед финальным шагом, чтобы не закрывать петлю раньше общей проверки
- Один H1, шаги 1-5, подготовка без номера, 13 кнопок копирования; пункты обоих оглавлений совпадают с H2, все id уникальны
- Прямые первоисточники стоят рядом с техническими фактами, цифры из обещания не перенесены
- Пересечений по предмету с web-search-v-claude и pyat-instrumentov-claude-code нет; обе ссылки находятся в «Дальше по теме»
- Нет длинных тире, запрещённых слов, гендерных обращений, служебного происхождения материала и рисунков интерфейса
- Help-banner и Лагерь из актуальной оболочки; CTA конкретный, без обещания построить все системы за указанный срок
- Остаточных замечаний к тексту и структуре не найдено

## Скиллы и пределы проверки

longform: обучающий текст для personal blog, 2351 слов с командами и служебными подписями после редактуры (точное число фиксируется inspection/verification), голос из _voice-profile.md и эталон живой статьи СКИЛЛЫ

Конфликты: готовое ТЗ задаёт структуру и запрет выдуманных ситуаций, поэтому личная история, обязательный главный ответ в первых 200 словах и TG-числовые нормы шаблона не применялись. Приоритет отдан конкретному ТЗ и правилу нарастания. Отсутствующий _format-canon-v2.md не подменялся выдуманным файлом

humaniser: снят повтор анонса другой статьи, сохранены прямые действия и объяснения предметов; нейросетевых клише и придуманных авторских сцен в финальном тексте нет

Browser/Safari, живые клики и входы с ключами не выполнялись: конкретное ТЗ поручает браузерную приёмку Claude и запрещает запуск Chrome. Синтаксис JS проверяется node --check, UI-скрипт совпадает с живой оболочкой СКИЛЛЫ
