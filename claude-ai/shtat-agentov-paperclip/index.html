Штат ИИ-агентов в Claude Code: Paperclip, роли и одна общая цель

Средний уровень

Когда поручений становится больше, чем один чат Claude Code успевает удержать, приходится самому передавать текст, напоминать про план и собирать ответы в один результат. Как дать эту работу директору, маркетологу и инженеру, а самому видеть, что они действительно движутся к одной цели?

С Paperclip ты соберёшь такую команду на своём компьютере. Это отдельное открытое приложение с панелью в браузере: в ней ты задаёшь цели, назначаешь роли, читаешь задачи и одобряешь планы. Claude Code выполняет работу, Paperclip хранит поручения и историю. Это похоже на общий рабочий стол команды, где у каждой задачи есть ответственный.

Paperclip не добавляет лимит Claude и не превращает агента в самостоятельного владельца проекта. Ты задаёшь исходные данные и принимаешь результат. Начнём с небольшой текстовой страницы, которую можно проверить без программирования. В последнем шаге разберём, какие записи и файлы показывают, что роли работали вместе.

Что нужно до начала

Открой VS Code с установленным Claude Code. Если его ещё нет, пройди инструкцию установки, войди в аккаунт и отправь обычное сообщение. Paperclip будет запускать этого же помощника на твоём компьютере через адаптер claude_local. Адаптер - соединение между панелью управления и программой, которая выполняет работу.

Поставь Node.js с официального сайта, версию 24.11 или новее. Это программа, с которой работает установщик Paperclip. Требование указано в README проекта. Вместе с Node.js появится команда npx, которая скачивает и запускает нужное приложение.

Создай отдельную пустую папку paperclip-workspace и открой её в VS Code через File → Open Folder («Файл → Открыть папку»). В меню Terminal → New Terminal («Терминал → Новый терминал») открой окно для команд. Вводи команды ниже туда, по одной, нажимая Enter после каждой:

node --version
npx --version
claude --version

Первый ответ должен быть v24.11.0 или выше, остальные два - номера версий. Если команда не найдена, закрой терминал и открой новый после установки соответствующей программы.

Чтобы не искать полный путь к папке вручную, отправь в чат Claude Code:

Покажи полный абсолютный путь к текущей папке paperclip-workspace. Ничего в ней не меняй. Мне нужно вставить этот путь в Local folder проекта Paperclip.

Локальный адаптер умеет читать файлы и выполнять команды. В его стандартной настройке подтверждения действий отключены, это описано в разделе Permissions («Разрешения»). Пустая папка отделяет учебные файлы от рабочего проекта, но сама по себе не ограничивает доступ агента к остальному компьютеру. Для первой проверки не подключай внешние сервисы и не клади в эту папку документы с личными данными.

Результат: три команды отвечают номерами версий, чат Claude Code работает, полный путь к пустой папке готов для настройки агентов.

Шаг 1. Запусти Paperclip на компьютере

В том же терминале введи команду из официального Quickstart («Быстрого старта»):

npx paperclipai@latest onboard --yes

Если npx спросит разрешение скачать пакет, введи y и нажми Enter. --yes принимает стандартные настройки мастера Paperclip. Он создаёт локальные данные и запускает панель. Оставь терминал открытым и открой в браузере http://localhost:3100, если окно не появилось само. Если установщик напечатал другой адрес, открой именно его.

localhost означает твой компьютер. Для этой проверки сервер в интернете не нужен. После перезапуска компьютера Paperclip можно снова открыть командой из инструкции установки:

npx paperclipai@latest run

Результат: в браузере открылась панель Paperclip с мастером создания организации. Сообщений об ошибке запуска в терминале нет.

Шаг 2. Создай организацию и подключи директора

На первом экране введи название Первая команда и нажми Continue («Продолжить»). Organization («Организация») - общее место для целей, агентов и задач. В документации создания организации ещё встречается слово Company («Компания»), но в мастере используется Organization.

Следующий экран предлагает первого агента. Назови его CEO (директор). Если мастер уже пройден, открой Agents («Агенты») → New Agent («Новый агент»). Первый агент получает роль директора; маркетолог и инженер будут подчиняться ему через Reports To («Руководитель»). Порядок создания описан в Hire Your First Agent («Первый агент»).

  1. Выбери адаптер Claude Code (claude_local) и локальное окружение на этом компьютере. В мастере подключения используй уже работающий вход Claude Code либо свой API-ключ.
  2. В Model («Модель») выбери модель, доступную в твоём аккаунте. Общую папку зададим проекту в шаге 5, до рабочей цели. Поле Working directory («Рабочая папка») в старых конфигурациях ещё встречается, но для новых настроек используется папка проекта.
  3. Оставь запуск по расписанию выключенным. Heartbeat («Рабочий запуск») - одно пробуждение агента: он читает поручения, делает работу и записывает результат. Для первого опыта расписание не требуется.
  4. В мастере нажми Run test («Проверить»), затем Finish setup («Завершить настройку»), когда проверка успешна. На полной странице агента проверка называется Test environment («Проверить окружение»). Кнопки текущего мастера описаны в описании интерфейса выпуска 2026.1001.0.

Тест проверяет команду claude, окружение и вход в аккаунт. Справка адаптера допускает вход по подписке Claude, API-ключ или настройки Bedrock. Если Claude Code уже работает по подписке, начни с этого входа. Если используешь API, сохрани ANTHROPIC_API_KEY как Secret («Секрет») и подключи его к агенту через переменные окружения. Ключ не вставляют в описание задачи или инструкции.

Проверка окружения сама обращается к модели с коротким тестовым запросом. Успешный тест ещё не запускает рабочую цель.

Результат: CEO есть в списке, проверка окружения успешна, рабочий запуск ещё не начат.

Шаг 3. Добавь маркетолога и инженера

Теперь директору нужны исполнители с разными обязанностями. Агент здесь - отдельная настройка Claude Code: имя, роль, инструкции и история работы. Paperclip связывает агентов руководителем, но содержание обязанностей задаёшь ты.

Через Agents → New Agent создай ещё двух агентов: Маркетолог и Инженер. Для обоих повтори настройку Claude Code, той же модели и локального окружения. После создания открой Configuration («Настройки») и в Reports to («Руководитель») выбери CEO. Не включай расписание. Проведи Test environment для каждого и сохрани настройки через Save («Сохранить»).

Открой Instructions («Инструкции») каждого агента. В списке Files («Файлы») выбери главный файл инструкций AGENTS.md, допиши в его редактор соответствующий текст ниже и нажми Save. Сохрани уже имеющиеся правила Paperclip. В текущем выпуске постоянные инструкции хранятся здесь, а старый promptTemplate отмечен как устаревший, что видно в коде редактора инструкций.

Инструкция директору CEO

Ты директор учебной команды. Прочитай общую цель организации. Сначала предложи стратегию и создай в Paperclip запрос одобрения типа approve_ceo_strategy. В нём покажи план, исходные данные и критерии приёмки. До одобрения не поручай исполнителям работу по цели.

После одобрения создай связанные с одной целью задачи: маркетолог готовит текст, инженер собирает итоговый файл, ты проверяешь результат. У каждой задачи укажи исполнителя, ожидаемый файл и критерии приёмки. Инженер начинает сборку после готовности текста маркетолога. Финал принимай после чтения файла, а не по сообщению исполнителя.

Работай только в настроенной рабочей папке. Не меняй настройки компьютера, не подключай сервисы, не публикуй результат. После выполнения учебной цели не создавай новых задач. Если чего-то не хватает, запиши препятствие в задаче.

Инструкция маркетологу

Ты маркетолог учебной команды, твой руководитель CEO. Выполняй назначенную тебе задачу Paperclip по общей цели. Подготовь marketing.md: заголовок, краткое объяснение продукта и три пользы для читателя. Не выдумывай цены, отзывы или статистику. Используй только учебные данные из цели.

Работай только в настроенной рабочей папке. Итоговый файл команды team-result.md не меняй. После сохранения marketing.md запиши его имя и результат в комментарии своей задачи. Если данных не хватает, отметь препятствие и обратись к CEO.

Инструкция инженеру

Ты инженер учебной команды, твой руководитель CEO. Выполняй назначенную задачу Paperclip по общей цели. Сначала прочитай готовый marketing.md. Если его ещё нет, отметь зависимость в своей задаче и сообщи CEO, не придумывай текст вместо маркетолога.

Создай team-result.md из текста marketing.md: один заголовок, объяснение продукта и три пункта пользы. Это текстовая структура страницы, код сайта писать не нужно. Добавь раздел «Проверка» с перечнем того, что вошло в файл. Работай только в настроенной рабочей папке. В комментарии задачи укажи файл и что проверено. Не публикуй результат.

Это учебное распределение обязанностей. Разные имена сами по себе не делают команду: инструкции задают, кто пишет исходный текст, кто его использует и кто принимает результат. Прежде чем дать им работу, ограничим расход.

Результат: три агента настроены, у двух исполнителей руководитель CEO, инструкции сохранены и все тесты окружения успешны.

Шаг 4. Поставь бюджеты до первого запуска

Агенты обращаются к модели самостоятельно. При входе через подписку они расходуют её лимит, при API-входе расход учитывается по тарифу сервиса. Бюджет Paperclip - денежный предел на зарегистрированный расход, а не число оставшихся сообщений Claude.

  1. Открой Costs («Расходы») → Budgets («Бюджеты»). В Monthly Budget («Бюджет на месяц») задай общий предел организации и нажми Save («Сохранить»).
  2. Открой CEO → Budget («Бюджет»), установи отдельный месячный предел и сохрани. Повтори для маркетолога и инженера. Вводи положительные суммы, которые разрешаешь потратить; универсальной суммы для всех аккаунтов нет.
  3. Вернись в Costs → Budgets и проверь, что видны все сохранённые пределы. Настройки и уровни ограничений описаны в справке бюджетов.

Эти пределы зависят от данных, которые передаёт адаптер. Не считай сумму в Paperclip гарантией сохранности квоты подписки: её расход смотри и в Claude. Разработчики предупреждают, что отчёт о расходе и уже начатая работа могут задержать остановку при достижении предела.

Для первой проверки оставь запуск по расписанию выключенным. Ограничь один рабочий запуск каждого агента:

  1. В Configuration раскрой Advanced Run Policy («Дополнительные правила запуска»). В Timeout (sec) («Время запуска, секунды», timeoutSec) введи 300.
  2. В разделе Advanced («Дополнительно») найди Max turns per run («Число ходов за запуск», maxTurnsPerRun) и введи 20.
  3. Выключи Continue after max-turn stop («Продолжать после остановки по числу ходов»), чтобы остановленный опыт не возобновлялся автоматически. Сохрани настройки.

Эти подписи есть в форме настроек и полях адаптера Claude. 300 секунд и 20 ходов - выбранные ограничения учебного опыта, не обещание, что задача успеет за них завершиться. Если времени не хватит, прочитай журнал перед повтором. Значение времени 0 в локальном режиме означает отсутствие такого ограничения, согласно справке адаптера.

Результат: общий бюджет и три бюджета агентов сохранены, расписание выключено, у каждого рабочего запуска есть ограничения.

Шаг 5. Поставь одну цель всей команде

Открой Goals («Цели») и создай цель с названием Первая текстовая страница. В описание вставь текст ниже и сохрани. Цель добавляется после создания организации, как объясняет справка Goals.

Подготовить текстовую структуру страницы учебного продукта «Список дел». Это простое приложение, в котором человек записывает дела, отмечает выполненные и видит оставшиеся. Эти сведения - все исходные данные. Цены, отзывы и дополнительные функции не придумывать.

Маркетолог создаёт marketing.md с одним заголовком, кратким объяснением продукта и тремя пунктами пользы. После него инженер читает marketing.md и собирает team-result.md с тем же содержанием и разделом «Проверка». CEO читает оба файла, проверяет соответствие цели и записывает приёмку в комментарии итоговой задачи.

Все задачи свяжи с этой целью и проектом «Первая текстовая страница», назначь нужным ролям. Используй настроенную Local folder этого проекта. Сначала предложи стратегию на моё одобрение, затем делегируй. Итог опыта: два файла в общей рабочей папке и комментарий CEO с результатом проверки. После этого остановись. Сайт не программировать и ничего не публиковать.

Теперь закрепи за этой целью общую папку. Открой Projects («Проекты»), создай проект Первая текстовая страница через Create project («Создать проект»). Подключать GitHub для этого опыта не нужно. Открой созданный проект → Configuration → Codebase («Рабочие файлы») → Set local folder («Задать локальную папку»). Вставь полный путь из подготовки и нажми Save. В Local folder («Локальная папка») должен появиться этот путь. Поля описаны в настройках проекта текущего выпуска.

В Description («Описание») проекта укажи: «Учебный проект по цели Первая текстовая страница. Все результаты сохранять в указанную Local folder». В инструкции CEO из шага 3 добавь: «Каждой задаче по этой цели укажи проект Первая текстовая страница и эту же цель». Связь задачи с проектом передаёт рабочую папку исполнителю, согласно описанию рабочих папок.

Здесь есть всё для первого опыта: исходные данные, порядок передачи работы и видимый результат. Пока CEO не начнёт работу, сохранённая цель остаётся поручением, поэтому следующий шаг - стратегия.

Результат: в Goals сохранена одна цель с двумя именами файлов и критериями проверки, а у проекта указана общая локальная папка.

Шаг 6. Запусти директора и одобри стратегию

Открой Agents → CEO и нажми Run Heartbeat («Запустить сейчас»). Для ручного запуска расписание включать не требуется: в описании рабочих запусков ручное обращение выделено отдельно от таймера.

Открой Runs («Запуски») в карточке CEO, затем запись текущего запуска. Статус running («Работает») показывает, что агент выполняет поручение. Прочитай журнал: директор должен увидеть цель и подготовить план. После завершения открой Approvals («Одобрения») и предложение Strategy («Стратегия»).

Проверь план перед согласием: текст делает маркетолог, инженер использует его файл, директор читает финал. В плане не должно быть публикации сайта, подключения сервисов или придуманной цены продукта. Если это есть, нажми Request revision («Попросить исправить») и напиши, что изменить. Подходящий план прими через Approve («Одобрить»). Эти действия описаны в инструкции первого запуска.

Одобрение может сразу поставить CEO в очередь на продолжение. Если он остался без нового запуска, снова нажми Run Heartbeat. Когда в Issues («Задачи») появятся поручения, прочитай их и проверь исполнителей, цель и проект «Первая текстовая страница». Если директор снова пишет только план или выполняет всё сам, оставь комментарий в его задаче. Если задачи у CEO ещё нет, создай её в Issues с названием «Делегировать учебную цель», назначь CEO в Assignee («Исполнитель»), укажи нашу цель и проект. В описание вставь текст ниже:

По одобренной стратегии создай отдельные задачи маркетологу и инженеру, свяжи их с целью и проектом «Первая текстовая страница». Укажи имена выходных файлов и что инженер ждёт готовый marketing.md. Итоговую проверку назначь себе. Покажи номера созданных задач.

После комментария или создания задачи запусти CEO вручную, если нового запуска нет. Если стратегии в Approvals не оказалось, вернись в Runs: проверь, что цель прочитана, инструкции сохранены и в журнале нет ошибки. Не переходи к исполнителям, пока план не представлен и не одобрен.

Результат: стратегия одобрена, на доске Issues видны задачи с именами исполнителей и общей целью.

Шаг 7. Проследи работу до итогового файла

Открой задачу маркетолога на доске Issues. Если её выполнение уже началось, дождись результата. Если нового запуска нет, открой Agents → Маркетолог → Run Heartbeat. В комментарии задачи должно появиться сообщение о файле marketing.md. Открой его в VS Code, в папке paperclip-workspace.

Теперь открой задачу инженера. После готовности исходного текста запусти инженера так же, если он ещё не работает. Задачи и комментарии поддерживают передачу работы между ролями, как описано в Task Workflow («Работа с задачами»). Если инженер остановился в статусе blocked («Заблокировано»), прочитай причину, сообщи в задаче, что исходный файл готов, и запусти агента снова.

В рабочей папке открой team-result.md. Он должен содержать заголовок, объяснение «Списка дел», три пользы и раздел «Проверка». Затем дай CEO завершить задачу приёмки, при необходимости через ручной запуск. В комментарии директор должен назвать прочитанные файлы и написать, соответствуют ли они цели. Если чего-то нет, оставь замечание в соответствующей задаче и повтори только нужный запуск.

Теперь можно ответить на вопрос из начала. В Issues открой задачи и проверь общую цель, назначения и комментарии. В Runs каждого агента открой завершённый запуск и найди его действия: маркетолог сохранил исходный текст, инженер прочитал его и собрал финал, CEO прочитал результат. Runs показывает ход работы и обращения к инструментам. Сравни журнал с реальными файлами, а не только со статусом done («Выполнено»).

Общая цель, связанная передача работы и файл, который прошёл проверку директора, показывают, что роли работали вместе. Три отдельных ответа без передачи результата между ними этой проверки не проходят.

После приёмки открой карточки агентов и переведи их в Pause («Пауза»). Выключенного таймера недостаточно для полной остановки: агенты могут просыпаться и от событий. Управление паузой описано в Managing Agents («Управление агентами»). Вернуться к работе можно через Resume («Продолжить»).

Результат: в папке есть marketing.md и team-result.md, комментарий CEO содержит приёмку, в Issues и Runs прослеживается вклад всех трёх ролей. Учебная команда поставлена на паузу.

Если не получилось

Установщик сообщает E404

Он мог обратиться к частному каталогу npm вместо общего. В README есть команда для установки из официального каталога:

npx --registry https://registry.npmjs.org paperclipai@latest onboard --yes
Панель не открывается или ошибка базы данных

Посмотри ошибку в терминале. Если Paperclip остановлен, используй команду повторного запуска из шага 1. Не запускай установщик с sudo или из терминала администратора: встроенная база данных этого не допускает. Для ошибки Embedded PostgreSQL на Mac с Apple Silicon есть отдельная ветка в документации установки. Передай Claude Code точный текст ошибки и попроси исправить её по этой странице.

Test environment не проходит

Проверь claude --version в терминале и обычное сообщение в чате Claude Code. Для задач в проекте сравни Local folder с полным путём из подготовки. Если журнал указывает на ACP, открой Configuration → Advanced → Execution engine («Способ запуска»), выбери Claude CLI (engine: cli, обычный запуск Claude Code), сохрани настройки и повтори тест. Справка ACP Engine объясняет: режим auto использует ACP и сам не переключается на CLI при несовместимом окружении.

Агент не продолжает работу

Открой Runs, затем проверь три места: ожидающее одобрение в Approvals, причину blocked в задаче и состояние бюджета в Costs. Если исчерпан лимит самой модели, дождись его восстановления. Если достигнут бюджет Paperclip, сохрани паузу либо измени предел осознанно после просмотра расхода. Не запускай агента многократно без чтения причины остановки.
