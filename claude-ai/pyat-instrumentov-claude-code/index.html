Шаг 1

Playwright: сайт проверяет себя сам

Когда кнопки приходится нажимать после каждой правки, установи браузерный CLI и его скилл в текущий проект

Установка и первый результат

  1. В терминале выполни

    npm install -g @playwright/cli@latest
playwright-cli install --skills

  2. Открой тестовую страницу и сделай снимок

    playwright-cli open https://example.com
playwright-cli screenshot
playwright-cli close

Что увидишь: после открытия появятся адрес, заголовок и путь к снимку структуры в .playwright-cli, а команда screenshot положит туда изображение

Скилл должен лежать в .claude/skills/playwright-cli текущего проекта. Если Claude Code открыт в другой папке, он эту инструкцию не увидит

Источник на 18.10.2026: официальная инструкция Playwright CLI для coding agents

Шаг 2

Supabase MCP: база данных из разговора

Если приложение хранит пользователей, заказы или записи, MCP даёт Claude Code доступ к одному указанному проекту Supabase без ручного перехода между окнами

Подключение и проверка

  1. Открой Settings → General в Supabase, скопируй Reference ID и подставь вместо <ID>. Затем добавь подключение только в настройки текущей папки Claude Code

    claude mcp add --scope project --transport http supabase "https://mcp.supabase.com/mcp?project_ref=<ID>&read_only=true&features=docs,database,development"

  2. Запусти Claude Code из этой папки, открой /mcp, выбери Supabase и пройди вход в браузере

  3. Попроси показать список таблиц, ничего не создавая

Что увидишь: команда добавит сервер в .mcp.json, а после входа статус сменится на Connected

В первом подключении уже включён read_only=true. Он оставляет чтение схемы и данных, но закрывает изменения. Переподключай сервер с правом записи только для отдельной осознанной задачи

Источник на 18.10.2026: официальная документация Supabase MCP

Шаг 3

Strix: отчёт о дырах до публикации

Когда проект уже принимает данные или деньги, обычной проверки интерфейса мало. Strix запускает агентов безопасности в Docker-песочнице и сохраняет найденные уязвимости отдельными файлами

Проверяй только свой проект или цель, на которую у тебя есть письменное разрешение. Для локального запуска нужны работающий Docker и доступ к выбранной модели. Папка монтируется в песочницу с правом записи, поэтому используй чистый сохранённый checkout без незакоммиченных файлов

Установка и безопасный первый запуск

  1. Установи текущую CLI по официальной строке

    curl -sSL https://strix.ai/install | bash

  2. Задай модель и ключ в переменных окружения по инструкции Strix. Ключ считай паролем и не сохраняй в файлах проекта

  3. Запусти короткую проверку чистой копии проекта. Параметр --max-budget 10 ограничивает расходы модели десятью долларами

    strix -n -t ./ --scan-mode quick --max-budget 10

Что увидишь: отчёт penetration_test_report.md, JSON и SARIF появятся внутри strix_runs/. Открой strix_runs/<run>/run.json: код 0 не доказывает отсутствия дыр, если проверка остановилась по бюджету или покрыла только часть проекта

Источник на 18.10.2026: официальный репозиторий Strix

Шаг 4

Skill UI: оформление сайта превращается в инструкции

Если нравится чужая система цвета, шрифтов и отступов, Skill UI делает снимки страницы и записывает найденные правила в папку, которую прочитает агент

Снять стиль и проверить файлы

  1. В папке проекта выполни

    npx -y skillui@latest --url https://адрес-сайта --mode ultra --screens 3 --out ./out

  2. Если команда пишет, что Playwright не установлен, выполни npm install playwright, затем npx playwright install chromium и повтори запуск

  3. Открой созданную папку в out и проверь DESIGN.md, SKILL.md и папку screens

Что увидишь: в папке out появятся правила цветов и шрифтов, повторяющиеся блоки и кадры страницы

Инструмент также может положить копию скилла в общую папку Claude. Если стиль нужен только одному проекту, проверь эту папку после запуска

Шаг 5

Context7: свежая документация вместо догадок

Последняя помеха появляется тише остальных: команда выглядит правдоподобно, но относится к старой версии библиотеки. Context7 подставляет документацию из текущего источника прямо в задачу

Подключение и первый запрос

  1. Запусти официальный мастер настройки

    npx ctx7 setup --claude

  2. Выбери MCP или режим CLI со скиллом, пройди вход по ссылке и дождись записи настройки

  3. Попроси актуальный пример для главной библиотеки проекта и добавь слова use context7

Что увидишь: ответ с актуальным синтаксисом и ссылками на документацию проекта вместо команды из памяти модели

Затем:
1. Через playwright-cli открой https://адрес-сайта и проверь главные кнопки
2. Через Supabase покажи список таблиц, но ничего не создавай и не меняй
3. Через Context7 возьми свежую документацию по главной библиотеке проекта

До установки всех пяти

Частые вопросы

Обязательно ставить все пять?

Нет. Начни с ручной работы, которую повторяешь сегодня. База и проверка безопасности нужны проекту позже, чем браузерная проверка или свежая документация

Где взять project_ref для Supabase?

Открой нужный проект, затем Settings → General и скопируй Reference ID. Он ограничит MCP одним проектом организации

Что означает бюджет Strix в 10 долларов?

Это верхний предел расходов модели на один запуск. Если бюджет закончился раньше, код 0 не доказывает, что весь проект проверен

Можно ли запускать Strix на чужом сайте?

Только с письменным разрешением владельца. Инструмент имитирует действия атакующего, поэтому обычной публичной ссылки недостаточно

Как проверить Context7 в режиме CLI?

Убедись, что создан скилл find-docs, затем получи ID через ctx7 library и запроси документацию через ctx7 docs

Если болит другое

Ещё пять вариантов из прежней подборки

Если в первой пятёрке нет твоей помехи, проверь ещё пять инструментов: для лимитов моделей, памяти между разговорами, длинных отчётов, подбора настроек и повторяющихся исправлений. Выбери один под текущую задачу, ставить все десять сразу не нужно

Дополнения для Claude Code: OmniRoute при исчерпании лимита

Задача остановилась на середине: Claude Code пишет, что лимит кончился. Без другого подключения остаётся ждать обновления

Здесь выручает OmniRoute. Он ставится на твой компьютер и работает посредником между Claude Code и нейросетями, такого посредника называют шлюзом. Запросы идут через него, а он решает, какая модель (вариант нейросети) ответит

Свежая установка может не иметь ни одной цели без ключа. Сначала подключи хотя бы одного провайдера, условия и лимиты которого тебе подходят

В режиме auto OmniRoute ранжирует доступные подключения динамически. Порядок с приоритетом подписки и более дешёвых моделей относится к стратегии auto/thrifty. Если нужна гарантированная модель, выбери или закрепи её явно

Это похоже на диспетчера такси: ты вызываешь машину, а какая из свободных приедет, решает диспетчер

OmniRoute не делает Claude безлимитным. Ответит та модель, которую выбрал текущий режим маршрутизации. Для задачи, где важен конкретный Claude, закрепи его вручную

У каждого подключённого сервиса свои лимиты, качество моделей и правила обращения с данными. Проверь их до отправки закрытого кода

Как начать:

OmniRoute требует Node.js в диапазоне >=22.22.2 <23 или >=24.0.0 <27. Если Node.js ещё нет на компьютере, установи его с официального сайта

  1. Открой терминал, установи OmniRoute глобально и запусти его

    npm install -g omniroute
omniroute

  2. В браузере открой http://localhost:20128

  3. В разделе Providers подключи сервис со своим ключом или подпиской и проверь, что он доступен

  4. Если подключаешь Claude Code вручную, скопируй ключ из раздела Endpoints: это локальный ключ OmniRoute

  5. Для быстрого запуска введи в терминале

    omniroute launch

    Команда откроет Claude Code и передаст ему нужный адрес и локальный ключ

Результат: Claude Code начнёт отправлять запросы через OmniRoute к подключённой модели

Шаги подключения есть в инструкции проекта OmniRoute, запуск Claude Code описан в инструкции того же проекта для Claude Code

claude-mem: когда надоело объяснять проект с нуля

Возвращаешься к проекту после перерыва, а Claude Code не помнит, что вы уже решили и какие варианты отбросили. Приходится снова пересказывать рабочую историю

claude-mem - плагин, то есть дополнение к Claude Code. Он сохраняет наблюдения между сессиями (отдельными рабочими разговорами): замечает действия инструмента, делает короткие сводки и подставляет нужные сведения при следующем запуске

Это как блокнот коллеги: он записывает важные решения и перед новой встречей открывает нужную страницу

Но это не дословная стенограмма всего разговора. Плагин сохраняет наблюдения и сводки, поэтому важные решения всё равно стоит держать в файлах проекта

Перед установкой посмотри в настройках, где будут храниться наблюдения и какой сервис будет обрабатывать память

Как начать:

  1. В Claude Code введи

    /plugin marketplace add thedotmack/claude-mem

  2. затем

    /plugin install claude-mem

  3. и перезапусти Claude Code

Результат: сведения о прошлых разговорах будут появляться в новых

  1. Другой способ - запустить в терминале

    npx claude-mem install

    и выбрать сервис памяти в ходе установки

Оба маршрута описаны в инструкции проекта claude-mem

Обычная команда npm install -g claude-mem устанавливает библиотеку, но не подключает плагин к разговорам

Headroom: когда мешают длинные технические отчёты

Просишь Claude Code найти ошибку, а он приносит длинный лог или сотни строк результатов поиска. Ему приходится учитывать весь этот текст в дальнейшей работе, и место для полезного разговора сокращается

Headroom - программа на твоём компьютере, которая сжимает материалы до того, как их увидит нейросеть. Она определяет, перед ней лог, код или обычный текст, и подбирает способ сжатия

Полный исходник остаётся локально. Рядом хранится короткое содержание, а нужную деталь можно запросить обратно

Headroom не добавляет Claude Code новый лимит и не гарантирует одинаковую экономию на каждом тексте

Режим wrap, в котором Claude Code запускается через Headroom, вдобавок устанавливает Serena, отдельную программу для поиска по коду. Этот шаг можно отключить параметром --code-memory none

Как начать:

  1. Открой инструкцию проекта Headroom

    Для приведённой там команды нужен uv, установщик программ для Python

  2. После его установки введи в терминале

    uv tool install --python 3.13 "headroom-ai[all]"

  3. Затем запусти

    headroom wrap claude

    команда запустит Headroom на твоём компьютере и откроет Claude Code через него

  4. Выполни

    headroom doctor

    чтобы проверить подключение

Результат: Claude Code получает сжатые материалы, а полный текст можно вернуть при необходимости

  1. Для следующего разговора снова запускай

    headroom wrap claude

Claude Code Setup: когда неясно, чем дополнить проект

Открываешь каталог расширений Claude Code и не понимаешь, что из него пригодится твоему проекту. Список большой, а задача у тебя вполне конкретная

Claude Code Setup - официальный плагин Anthropic, который просматривает файлы проекта и предлагает подходящие настройки работы

Он может посоветовать скилл (готовую инструкцию для повторяющейся задачи), хук (действие, которое запускается автоматически), команду, отдельного помощника или MCP-сервер для подключения внешнего инструмента

Похоже на мастера, который сначала осматривает рабочее место, а уже потом говорит, какой инструмент добавить

Плагин не устанавливает всё предложенное и не меняет файлы за тебя. Его задача - дать рекомендации, из которых ты выбираешь нужное

Как начать:

  1. Открой Claude Code в папке проекта и установи плагин из официального каталога

    /plugin install claude-code-setup@claude-plugins-official

    Открой /plugins, убедись, что Claude Code Setup находится в Installed, затем напиши

    recommend automations for this project

Результат: Claude Code предложит подходящие дополнения по категориям

  1. Возьми одно, которое помогает с текущей задачей, и реши, нужно ли его подключать

Task Observer: когда одни и те же правки повторяются

Ты снова исправляешь Claude Code одну и ту же ошибку: просишь короче, возвращаешь нужный тон или напоминаешь о пропущенном шаге. После нескольких задач хочется, чтобы эта поправка попала в постоянные инструкции

Task Observer - скилл, то есть папка с инструкциями для ИИ-помощника. Пока ты работаешь, он замечает повторяющиеся действия, твои исправления и пробелы в других скиллах

Затем записывает наблюдения и предлагает, какую инструкцию создать или поправить. Это как редактор, который ведёт список повторных замечаний, чтобы следующую работу начать уже с учётом них

Сам Task Observer не переписывает твои скиллы. Предложения остаются на твоём рассмотрении

И простое копирование папки ещё не включает наблюдение: по инструкции проекта нужно отдельно настроить запуск скилла в новых разговорах

Как начать:

  1. Установи комплект командой

    npx skills add rebelytics/one-skill-to-rule-them-all --skill task-observer

    или скачай его со страницы проекта Task Observer от rebelytics, сохранив вместе SKILL.md, references/ и scripts/

  2. Затем добавь правило запуска по файлу references/environments.md и проверь его в новом разговоре

Результат: после нескольких рабочих разговоров в skill-observations/observation-log/ появятся записи, которые можно просмотреть перед правкой скиллов
