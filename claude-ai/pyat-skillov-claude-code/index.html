Пять скиллов для Claude Code: поиск, план, память, дизайн и один, который учит остальные

Средний уровень

Claude Code стоит, а работать с ним всё равно тяжело: утром он не помнит, что вы решили вчера, на любую просьбу сразу лезет править файлы, сайты выходят одинаковые, а ту же ошибку приходится поправлять в пятый раз. Пять дополнений снимают эти помехи по одной. Ниже каждое ставится одной командой и проверяется одной фразой, так что сразу видно, заработало или нет.

Самое интересное - пятое. Оно запоминает твои поправки и предлагает, как исправить остальные скиллы, чтобы в следующий раз объяснять не пришлось. Как это устроено и где здесь твоё слово, в последнем шаге.

Два слова, которые встретятся дальше. Скилл - готовая инструкция, по которой Claude Code делает определённую работу. Плагин - дополнение, внутри которого может лежать несколько скиллов и других настроек. Superpowers и claude-mem ставятся как плагины, остальные три - как скиллы.

Скиллы для Claude Code: что нужно до установки

  • Claude Code в VS Code. Если его ещё нет, начни с установки Claude Code в VS Code. Для работы нужна подписка Pro, Max, Team или Enterprise либо аккаунт Console, так написано в инструкции Anthropic.
  • Node.js. Скачай версию с пометкой LTS («с долгой поддержкой») с официального сайта. Вместе с ним появится команда npx, через которую ставятся три скилла из пяти. Для claude-mem нужна версия 20 или новее, это указано на странице проекта.
  • Одна папка проекта. Все пять шагов делай в ней. Не хочется экспериментировать на рабочем сайте - создай пустую папку и открой её в VS Code.

Команды в статье бывают двух видов, и вводятся они в разных местах:

  • Команды с npx - в Terminal («Терминал», окно для команд). В VS Code он открывается через меню Terminal → New Terminal («Терминал → Новый терминал») и сразу стоит в папке проекта.
  • Команды со слэшем, например /plugin или /impeccable, и просьбы обычными словами - в чат Claude Code. Каждую отправляй, только когда пришёл ответ на предыдущую.

Проверь, что Node.js на месте. Введи в терминале по очереди две команды, каждая должна ответить номером версии:

node --version
npx --version

Вместо номера пишет «command not found» («команда не найдена»)? Закрой терминал и открой новый: старое окно не видит только что установленный Node.js.

Если чат в VS Code не принимает команды /plugin

В панели VS Code плагины можно ставить мышкой. Напиши в чате /plugins, откроется окно Manage plugins («Управление плагинами»). На вкладке Marketplaces («Каталоги») добавляются каталоги, на вкладке Plugins («Плагины») ищешь нужный и жмёшь Install («Установить»). Так написано в документации Anthropic.

Второй путь - запустить Claude Code прямо в терминале. Открой ещё один терминал и введи:

claude

Когда появится поле для сообщения, вводи команды /plugin туда. Если терминал не знает команду claude, поставь Claude Code для терминала по инструкции Anthropic: расширение VS Code её не добавляет.

Шаг 1. Find Skills: найди скилл под свою задачу

Скиллов уже тысячи, и угадать, какой нужен под твою задачу, трудно. Find Skills ищет их за тебя. Это скилл от компании Vercel: ты говоришь Claude Code, что собираешься делать, а он ищет подходящие в каталоге skills.sh.

В ответ приходит список: что делает каждый скилл, кто его выложил, сколько раз его поставили и какой командой подключить. По его инструкции он советует брать скиллы, у которых больше тысячи установок, и ставит выбранный только после твоего «да».

Ставим его первым, потому что дальше им же можно искать всё остальное. Введи в терминале:

npx skills add vercel-labs/skills --skill find-skills -a claude-code

Приписка -a claude-code говорит, что скилл ставится для Claude Code. Если установщик спросит, куда ставить, выбери текущий проект. Потом открой новый чат Claude Code в этой же папке и отправь:

Найди скилл для проверки доступности сайта. Покажи варианты, что каждый проверяет, откуда он и сколько у него установок. Предложи подходящий, но дождись моего согласия перед установкой.

Доступность - это удобно ли пользоваться сайтом тем, кто ходит по странице клавиатурой или слушает её через программу чтения с экрана.

Как искать и управлять скиллами из терминала

Поиск по слову accessibility («доступность»):

npx skills find accessibility

Какие скиллы уже стоят:

npx skills list

Обновить все поставленные скиллы:

npx skills update

Результат: на просьбу найти скилл приходит список вариантов с числом установок, а ставит Claude Code только тот, на который ты согласишься.

Шаг 2. Superpowers: сначала план, потом файлы

Просишь добавить на сайт один блок, а Claude Code уже переписал три файла, хотя вы толком не договорились, что должно получиться. Superpowers заставляет его притормозить. Это плагин с набором скиллов, который выстраивает работу по порядку.

Порядок такой, по описанию разработчика:

  1. Claude Code расспрашивает, чего ты на самом деле хочешь.
  2. Показывает замысел короткими кусками, чтобы его можно было прочитать и одобрить.
  3. Составляет план работы.
  4. После твоего «делай» выполняет план по задачам и проверяет каждую.

Включать ничего не нужно, скиллы срабатывают сами, когда видят задачу. Ошибки это не отменяет, зато неверное решение видно на этапе замысла, а не после переделки половины проекта.

Superpowers есть в официальном каталоге плагинов Anthropic. Введи в чате Claude Code:

/plugin install superpowers@claude-plugins-official
Если официальный каталог не находит Superpowers

Поставь его из каталога самого разработчика. В том же чате по очереди: первая команда добавляет каталог, вторая ставит плагин.

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

Перезапусти Claude Code и дай ему задачу, в которой есть что обсудить:

Хочу добавить на сайт блок с вопросами клиентов и ответами. Если страницы ещё нет, начнём с одной простой страницы. Помоги выбрать, как её устроить.

Ответь на его вопросы, одобри замысел, потом план. Когда страница готова, попроси показать, в каком она файле: эта страница пригодится в шаге 4.

Результат: Claude Code начинает с вопросов и плана, а файлы меняет только после твоего разрешения.

Шаг 3. claude-mem: новый чат помнит прошлую работу

Закрываешь чат, открываешь новый - и всё рассказываешь заново: что за проект, что уже сделано, что решили. claude-mem избавляет от этого пересказа. Плагин записывает ход работы, сжимает его в короткие заметки и подкладывает нужные в начало следующего разговора.

Это заметки, а не дословная запись переписки, поэтому важные решения всё равно стоит держать в файлах проекта. Что ещё умеет плагин, разобрано в статье «Пять дополнений для Claude Code». Здесь ставим и проверяем, что память правда работает.

Введи в чате Claude Code по очереди две команды из инструкции claude-mem и перезапусти Claude Code:

/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem

Кто обрабатывает память. Заметки составляет нейросеть, и она расходует чей-то лимит. Если ставить через терминал командой из блока ниже, установщик предложит выбор: сервис claude-mem, свой ключ OpenRouter или Gemini либо твоя подписка Anthropic. Сервис claude-mem первые до 14 дней не тратит лимит твоей подписки, потом память переходит на подписку Anthropic, если не оформить их собственную. Это касается только памяти, остальная работа Claude Code идёт как обычно.

Установка через терминал с выбором, кто обрабатывает память

Это другой способ поставить тот же плагин. Выбери один из двух, оба делать не нужно:

npx claude-mem install

Установщик попросит войти по ссылке, которая придёт на почту, банковская карта не нужна. Потом спросит, кто будет обрабатывать память. Ключ OpenRouter или Gemini - это личный пароль от сервиса, в обычный чат его не вставляй.

Входить не хочется - добавь к команде флаг --provider с выбранным вариантом. Все настройки потом лежат в файле ~/.claude-mem/settings.json, и Claude Code может объяснить, что там выбрано.

Теперь дай памяти что запомнить. В текущем чате отправь:

Посмотри файлы проекта и запиши в README, какую страницу мы собираем и для кого она. Следующий шаг - проверить эту страницу с Impeccable. Если README ещё нет, создай его.

Когда файл записан, открой новый чат в той же папке и, ничего не пересказывая, спроси:

Над чем мы работали в прошлой сессии и какой следующий шаг согласовали? Сначала используй память claude-mem, без чтения README, и укажи, на какую сохранённую запись опираешься.

Просьба не читать README нужна, чтобы отличить память от простого чтения файла. Ответа нет - смотри «Если не получилось».

Результат: в новом чате Claude Code сам называет прошлую задачу и следующий шаг и показывает, на какую заметку claude-mem опирается.

Шаг 4. Impeccable: замечания к дизайну страницы

Страница из шага 2 работает, но выглядит как сотня других, собранных нейросетью: те же цвета, те же карточки, мелкий серый текст. Impeccable учит Claude Code видеть такие вещи. Он вырос из скилла frontend-design от Anthropic и знает 61 признак, по которому сгенерированный дизайн видно сразу.

Внутри одного скилла 24 команды: проверить страницу, разобрать дизайн, отполировать перед публикацией и другие. Решать, какие замечания принять, всё равно тебе. Чем лучше он знает твой продукт и читателей, тем точнее советы, поэтому начинается всё с короткого знакомства.

Введи в терминале команду установки:

npx impeccable install

Установщик сам найдёт Claude Code и спросит, ставить в этот проект или во все. Выбери этот проект. Перезапусти Claude Code и один раз отправь в чат:

/impeccable init

Он задаст вопросы про продукт и читателей и сохранит ответы в файл PRODUCT.md, к которому будет возвращаться в каждой следующей проверке. Теперь проверка страницы:

/impeccable audit

Если спросит, какую страницу смотреть, назови файл из шага 2. Audit («Проверка») смотрит, удобна ли страница для всех, быстро ли грузится и как выглядит на телефоне. Например, отметит бледный текст, который сливается с фоном, или кнопку, в которую трудно попасть пальцем.

Ещё две команды пригодятся после проверки. Их отправляют в тот же чат, полный список есть в описании Impeccable:

  • /impeccable critique («Разбор») - мнение о дизайне: что цепляет взгляд, что путает.
  • /impeccable polish («Полировка») - последний проход перед публикацией.

Короткая команда /audit без слова impeccable появится, только если создать её командой /impeccable pin audit.

Результат: на /impeccable audit приходит список конкретных замечаний именно к твоей странице.

Шаг 5. Task Observer: поправка становится правилом

Четыре скилла стоят, а одно и то же всё равно приходится повторять: проверь на телефоне, пиши короче, не трогай этот файл. В новом проекте всё сначала. Task Observer замечает такие поправки и превращает их в правила для остальных скиллов.

Пока ты работаешь, он ведёт журнал: какие поправки ты делаешь, что предпочитаешь, где скиллам не хватает инструкций. Из журнала он готовит конкретные правки к скиллам и предлагает новые. Следит и за собой, поэтому со временем наблюдает точнее. Подробнее о нём в статье «Пять дополнений для Claude Code».

Сам он скиллы не переписывает. Каждую правку ты читаешь и одобряешь, только после этого она попадает в скилл. И одной установки мало: нужно правило, по которому он включается в каждом новом чате, иначе он почти не срабатывает. Обе вещи сделаем ниже.

Поставь скилл. Введи в терминале:

npx skills add rebelytics/one-skill-to-rule-them-all --skill task-observer -a claude-code

На вопрос, куда ставить, оставь текущий проект. Чтобы он работал во всех проектах сразу, к команде добавляют -g.

Теперь правило запуска. Оно записывается в CLAUDE.md - файл с постоянными правилами проекта, который Claude Code читает в начале каждого чата. Вручную ничего переносить не нужно, отправь в чат просьбу, и Claude Code сам настроит всё по инструкции Task Observer:

Настрой установленный Task Observer для этой папки проекта. Прочитай его SKILL.md и references/environments.md. Проверь, что рядом сохранены папки references и scripts.

Добавь в CLAUDE.md правило: в начале каждого нового чата, до первого обращения к инструментам и до составления плана, загрузить Task Observer и выполнить его стартовую проверку (Session Start Protocol).

Укажи реальные полные пути к скиллу, журналу наблюдений и предложениям правок. Создай нужные папки, не оставляй примерные пути. Если CLAUDE.md ещё нет, создай его. Покажи добавленное правило и где будут лежать записи. Остальные скиллы пока не меняй: сначала покажи предложение и дождись моего одобрения.

Правило срабатывает в начале чата, поэтому проверять его нужно в новом. Открой новый чат в той же папке и отправь:

Посмотри нашу страницу и предложи одну доработку.

В начале ответа должно быть видно, что Task Observer загрузился сам, без напоминания. Не видно - попроси показать его стартовую проверку и путь к журналу. Включился только после просьбы - значит, правило не сработало, повтори настройку и проверь снова в новом чате.

Теперь самое главное. Дай Claude Code настоящую поправку, например «перед сдачей всегда проверяй кнопки на телефоне», и отправь:

Покажи, где Task Observer записал мою поправку. Предложи конкретное изменение подходящего скилла, чтобы учитывать её в следующих задачах. Покажи текст правки и дождись моего одобрения.

Прочитай, что он предлагает. Подходит - одобри и попроси показать, как теперь выглядит скилл. Вот и весь круг: ты один раз поправляешь, Task Observer записывает, предлагает правку, ты соглашаешься - и в следующей задаче, в любом проекте с этим скиллом, Claude Code уже делает по-новому. Так пятый скилл и улучшает остальные: не сам по себе, а из твоих поправок и с твоего согласия.

Результат: в новом чате Task Observer включается сам, твоя поправка появляется в журнале, а правка скилла ждёт твоего одобрения.

Как пять работают вместе

Возьми одну маленькую задачу, например доработать блок с вопросами из шага 2, и пройди её целиком:

  1. Find Skills подбирает скилл для проверки доступности, ты соглашаешься на подходящий.
  2. Superpowers не даёт начать без замысла и плана.
  3. claude-mem в новом чате напоминает, что изменили и что осталось.
  4. Impeccable проверяет страницу и даёт список замечаний.
  5. Task Observer записывает твою поправку и предлагает правку скилла.

После такого прохода следующая задача начинается не с нуля: проект Claude Code помнит, а твои поправки уже лежат в скиллах.

Если не получилось

Терминал не знает команду npx

Поставь Node.js с пометкой LTS, закрой терминал, открой новый и снова введи npx --version. Не помогло - отправь в чат Claude Code:

В терминале VS Code команда npx не найдена. Помоги проверить установку Node.js и подскажи, как открыть терминал в папке этого проекта. Объясняй по одному действию.
Плагин не появился после установки

Перезапусти Claude Code в той же папке и открой список плагинов:

/plugin

Найди в списке нужный плагин и проверь, что он включён. Его там нет - отправь:

После установки и перезапуска не вижу нужный плагин. Помоги проверить список через /plugin и объясни, что означает сообщение установщика. Сначала спроси название плагина и текст ошибки.
claude-mem установлен, а памяти нет

Частая причина - установка командой npm install -g claude-mem. Она ставит только библиотеку для программистов, а сам плагин не подключает, об этом предупреждают разработчики. Поставь заново способом из шага 3, перезапусти Claude Code и сделай небольшую задачу. Память так и не появилась - отправь:

claude-mem не вспоминает работу в новом чате той же папки. Проверь, подключён ли плагин, работает ли служба памяти и кто её обрабатывает. Покажи причину и одно действие для исправления, без вывода моих ключей.
Task Observer молчит
